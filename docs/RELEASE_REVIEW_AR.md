# دليل مراجعة إصدار Digital Product Studio

هذه حزمة مراجعة، وليست إذناً بالنشر. تم دمج PR #58 في متابعة أخرى؛ تُراجع التغييرات اللاحقة في فرع منفصل عن main؛ لا تدمج أو تنشر دون موافقة صريحة. الاستضافة الحالية Render، وعقد Netlify بديل موجود في المستودع. لا يُطلب شراء دومين أو خدمة جديدة.

## التشغيل على Windows / PowerShell

```powershell
git clone https://github.com/rahman-997/portfolio.git
cd portfolio
git switch feat/digital-studio-conversion-2026-11-24
node --version
npm --version
npm ci
npm run dev
```

استخدم Node 22.13.0 (ملف .node-version) وnpm 11.19.1. للتصدير القابل للمراجعة أغلق خادم التطوير أولاً:

```powershell
$env:GITHUB_SHA = (git rev-parse HEAD).Trim()
npm run lint
npm run typecheck
npm run build
npm run verify:export
npm run audit
node scripts/release-candidate.mjs create out release-manifest.json $env:GITHUB_SHA
node scripts/release-candidate.mjs verify out release-manifest.json
python -m http.server 4173 --bind 127.0.0.1 --directory out
```

افتح http://127.0.0.1:4173/ ثم /ar/ و/tr/ . لا تستخدم next start مع output: export. يمكن تنزيل حزمة portfolio-review-<SHA> من CI للفرع التجاري (مدة الاحتفاظ 7 أيام) عند نجاح خطوة الحزمة؛ بعد فك الضغط افحص البصمة باستخدام السكربت من نفس commit. مجلد out هو ناتج الاستضافة؛ ملف release-manifest.json خارج المجلد للمراجعة فقط.

## شروط اعتماد الإصدار

- نجاح CI والأمان وBrowser QA وLighthouse على نفس SHA، وليس على فرع قديم. إذا تعطل npm audit خارجياً، لا تعتبر التحذير دليلاً على خلو الاعتماديات من الثغرات.
- مراجعة مخرجات الحزمة ولقطات المتصفح؛ حالة الاختبار على الأجهزة: لم يُجرَ اختبار على هاتف أو جهاز Windows فعليين. المنفَّذ فقط محاكاة Chromium بعروض 390 و820 و1280 باللغات الثلاث والوضعين وسكربت v4-browser-qa. نجحت حالات Firefox وWebKit في تشغيل CI للنسخة ff20e08؛ لا يزال Safari/iOS على جهاز فعلي غير مختبر. المخاطر المتبقية المحددة: سلوك عنصر dialog وdvh وbackdrop-filter ودرج التنقل باللمس على iOS. هذا ليس نجاحاً على أجهزة حقيقية، ولا يُعتبر مانعاً للدمج إذا نجحت بقية الفحوص.
- تمييز الديمو العام والمعاينة المحدودة وعدم وجود رابط؛ لا تدّعِ أن كل تطبيق صالح للبيع. أعد فحص Eventify وVenues API وBookHaven قبل الاعتماد التجاري.
- Lighthouse 95+ هدف أداء وليس نتيجة مثبتة. LCP ما زال يحتاج تحسين؛ قياسات المختبر ليست بيانات زوار حقيقية.
- لا ترفع أي صور خاصة أو أسرار أو بيانات عملاء. لا تنشر الملفات التاريخية المتضررة كصور معاينة.
- لا تغيير في main أو الإنتاج أو DNS أو الفوترة. Render وNetlify لديهما إعدادات نشر مرتبطة بفرع main؛ الدمج قد يطلق نشراً تلقائياً. يجب اعتماد الدمج والنشر بشكل صريح أولاً.
- قبل أي نقل لاستضافة أخرى: تحقق من حدود الخطة المجانية الحالية، إعدادات HTTPS/headers، canonical/sitemap، مسارات trailing slash و404. حافظ على عنوان الإنتاج الحالي إلى أن يُعتمد البديل.

بعد موافقة منفصلة على النشر: تحقق من SHA المنشور وفحص HTTP وملفات CV/briefs، روابط المِلاحة، SEO، وأمان الهيدرز. عند الإخفاق أوقف الترقيات وحدد آخر SHA مستقر وخطة استرجاع قبل تنفيذ أي rollback.

## التحقق من HTTP محلياً

بعد تشغيل الخادم المحلي، افتح نافذة PowerShell أخرى داخل المشروع ونفّذ `node scripts/verify-candidate-http.mjs release-manifest.json http://127.0.0.1:4173`. يتحقق من بصمة كل ملف كما يرسله الخادم وتسعة مسارات فعلية. ليس فحصاً للاستضافة المنشورة.

## مختبر الأداء المضغوط

اختبارات Lighthouse تحتفظ بالقياس غير المضغوط وتقيس سيناريو gzip منفصلاً للغات الثلاث على نفس البناء. قارن حجم النقل وLCP وTBT بين السيناريوهين؛ هذا لا يثبت إعدادات ضغط Render أو Netlify ولا يثبت تحسناً عند الزوار. لا يتم تعديل ملفات الاستضافة أو نشرها. الهدف هو فصل كلفة النقل عن كلفة تنفيذ JavaScript.

## فحص النقل على الموقع المنشور

تقرير `published-delivery-<SHA>` يفحص HTML وملف JS وCSS إن وُجدا على عنوان Render الحالي بطلبات GET فقط، ويقارن بصمات المحتوى بعد فك gzip وحجم جسم الاستجابة. يميّز تعذر الاتصال واختلاف المحتوى عن غياب الضغط. هذا التقرير لا يمثل أداء النسخة غير المنشورة، ولا يتطلب تعديل الاستضافة.

## توافق محركات المتصفح

أُضيفت وظيفتا Firefox وWebKit إلى Browser QA، بست حالات لكل محرك (ثلاث لغات ووضعان على عرض 375px). WebKit يستخدم محاكاة اللمس. تشمل تبديل المشروع وdialog والقائمة والفلاتر والبحث وFAQ والاتجاه وحدود الشاشة. هذه محاكاة Linux وليست Safari على iPhone أو اختبار Windows فعلياً؛ لا تعتبرها ناجحة حتى تكتمل الوظائف على SHA المرشح. لا يُعتمد الإصدار بسبب نجاح Chromium وحده.

## صيانة مسار التسليم (مقترح للمراجعة)

فحص الإنتاج بتاريخ 25 نوفمبر 2026 أكد SHA `8c1cca8a` على Render، مع تحذير غياب X-Frame-Options وReferrer-Policy وCross-Origin-Opener-Policy وCross-Origin-Resource-Policy. تفعيلها يتطلب صلاحية إعدادات الاستضافة وموافقة منفصلة؛ لم تتغير إعدادات الإنتاج. Netlify فشل بسبب غياب مفتاح الوصول، وليس بسبب البناء. يقترح هذا الفرع جعل Netlify اختيارياً عبر workflow_dispatch على main فقط، مع تأكيد صريح وSHA مطابق لآخر CI ناجح ودليل SHA-256. لا تُضف أسراراً ولا تشغّل النشر دون موافقة. حزمة main المقترحة تقتصر على out وmanifest، وتحتاج CI جديداً بعد دمج معتمد قبل استخدامها. لا يضمن فحص SHA الذريّة بين التحقق والنشر؛ يجب تجنب تغييرات main أثناء عملية النشر المعتمدة.
